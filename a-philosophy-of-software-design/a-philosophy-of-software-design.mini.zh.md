# 遵循《软件设计哲学》（John Ousterhout）

## 何时使用

用于模块设计、API 变更、模块分解、重构、命名、注释、测试、性能工作，以及那些让人感觉别扭或让复杂度扩散到多个文件的改动。

## 需要纠正的首要偏见

能跑起来的代码、细碎的小片段、熟悉的模式、标志参数、包装层和额外的文档，如果它们抬高了认知负担或泄漏了知识，就不会让设计变简单。

## 决策规则

- 把复杂度的降低作为首要成功指标。优先选择那个能降低认知负担、变更放大效应、隐藏依赖、时序耦合，以及读者需要同时记住的事实数量的设计。
- 把设计当作持续性的工作。一个初次可用的补丁，如果恶化了未来的可变更性，就不算完成；对于非平凡的接口、分解或抽象选择，要比较几个可行的备选方案。
- 优先选择深模块：接口小而具语义，内部隐藏了实质性的复杂度。拒绝纯转发的服务、薄薄的库包装层、辅助模块，以及那些只增加名字却不减轻读者负担的细碎拆分。
- 围绕调用方需要知道什么来设计接口，而不是围绕实现如何工作。避免脆弱的分阶段调用、初始化序列、模式标志、配置开关，以及暴露内部选择的参数。
- 把易变的决策、内部表示、存储形状、协议、文件格式、性能技巧、记账逻辑、归一化处理和杂乱的边界处理，隐藏在拥有这些知识的模块内部。
- 当下层模块本就拥有某个细节时，把复杂度向下压。如果稍微复杂一点的实现能给调用方一个更简单的公开契约，并免去各调用点重复的推理，那就值得。
- 在合适的层级上选择通用性。避免只为一个调用方过度拟合、含义模糊的推测性抽象，以及被罕见边界情况污染的核心路径；用"特例—通用"分解把特殊行为隔离出去。
- 依据总体复杂度来合并或拆分，而不是依据体积、运行时顺序、习惯或审美。把相关的状态、行为、不变式和设计决策放在一起，除非新的边界更深且能被独立理解。
- 在可能的情况下，通过改变接口或不变式来缩小异常面。把非法状态和别扭的情况在定义层面消除掉，而不是让每个调用方都重复一遍防御性的仪式。
- 用注释来降低复杂度：记录接口契约、不变式、隐藏的设计决策、决策理由，以及调用方本不应需要了解的棘手实现事实。不要叙述代码，也不要用注释弥补糟糕的命名、拙劣的分解或混乱的流程。
- 把命名、一致性和"显而易见"当作设计信息。名字应当揭示抽象而非机制；相关的操作应当共享同一套约定；令人意外的代码即使很短也是复杂度。
- 用测试通过公开契约和稳定 API 来保护行为，尤其是围绕被隐藏的复杂度和被隔离的特例。不要让测试的便利性逼出浅薄或泄漏的接口。
- 只有当性能优化、潮流、范式、模式或框架能降低本代码库的复杂度，或有证据表明这个权衡确实重要时，才引入它们；把优化细节藏在稳定接口之后。

## 触发规则

- 当某个功能让人感觉别扭、一次改动波及多个文件，或评审者必须重建隐藏依赖时，去寻找缺失的信息隐藏、浅薄的模块、时序耦合，或被推给调用方的复杂度。
- 当要新增一个模块、分层、服务、辅助函数、包装器、门面、模式、选项、回调或参数时，先证明它隐藏的复杂度多于它引入的复杂度。
- 当改动一个 API 时，检查普通调用方是否必须了解调用顺序、表示形式、存储、传输、缓存、协议、文件格式、内部流程，或过多的初始化步骤。
- 当要新增一个特例、标志、异常路径、条件判断或对外暴露的容器时，先问问拥有该职责的模块能否消除这个非法状态、隔离这种异常行为，或提供一个更强的操作。
- 当做拆分、提取或引入变量时，检查新的边界或名字是否捕捉到了含义，还是只增加了跳转、纯转发的状态和可见的中间步骤。
- 当代码被组织成 `prepare/process/finalize`、分阶段对象或其他按执行顺序划分的阶段时，确认时序结构确实是真正的概念；否则应围绕稳定的职责重新组织。
- 当命名含义模糊、偏重机制、前后不一致或令人意外时，重新审视抽象边界，而不是接受一个"差不多"的名字。
- 当注释越写越长、重复了代码、在为一个令人困惑的接口辩解，或通过暴露内部结构来解释用法时，重新设计这个抽象，或把缺失的契约挪到接口上。
- 当做性能优化时，先测量，并把优化隐藏起来；在没有证据表明这个权衡重要之前，不要牺牲模块深度或信息隐藏。
- 当测试或评审时，聚焦于公开行为、接口契约、通过稳定 API 呈现的隐藏复杂度，以及被隔离在抽象之后的特例。

## 最终检查清单

- 这次改动是否降低了理解、修改、验证和扩展系统所需的精力？
- 每一个接口元素、包装器、分层、辅助函数、选项和名字，隐藏的复杂度是否足以证明其存在的合理性？
- 重要的决策是否局部化，依赖是否可见，调用方需要知道的约束是否已记录，可变的内部结构是否受到保护？
- 常见情况是否变得自动化，而罕见的控制手段、特例、性能技巧和异常细节是否都留在了常规路径之外？
- 名字是否精确一致，注释是否与代码同步且不重复代码，除非有新信息证明应当改变，是否遵循了既有约定？
